# Домашнее задание № 8: Пул потоков

Java-приложение отправляет GET-запросы параллельно в собственном `ThreadPoolExecutor`, печатает статусы и длительности, сохраняет CSV и выводит сводку. Требуется JDK 21 или новее. Сторонних библиотек нет.

## Быстрый запуск в Windows

Откройте терминал в папке проекта:

```powershell
.\run.cmd
.\test.cmd
```

Скрипт найдёт JDK через JAVA_HOME, PATH или каталог `.jdks`, который использует IntelliJ IDEA. Первый запуск компилирует исходники. Внешний доступ нужен только для запросов к публичным URL; локальные тесты работают без Интернета.

Пример настройки:

```powershell
.\run.cmd --urls urls.txt --core 4 --max 8 --queue 8 --keep-alive 30 --timeout 10 --output results.csv
```

Сборка без запуска: `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Action Build`.

## Запуск в IntelliJ IDEA / Giga IDE

1. Откройте папку проекта или `pom.xml` как проект Maven.
2. Выберите Project SDK 21+ и язык Java 21.
3. Запустите `ru.homework.threadpool.Main`. Working directory должна указывать на папку проекта с `urls.txt`.
4. Для проверки запустите `ru.homework.threadpool.IntegrationTest` из `src/test/java`, либо `test.cmd` в терминале.

`pom.xml` предназначен для импорта и компиляции. Интеграционный тест — обычный Java main, поэтому `mvn test` сам его не запускает. Скрипты не требуют Maven и не скачивают зависимости.

## Формат входных данных

`urls.txt`: один абсолютный HTTP/HTTPS URL на строку. Пустые строки и строки с `#` пропускаются. Адреса со встроенными логином/паролем отклоняются. Повторяющиеся URL разрешены: каждый считается отдельной задачей. Пример содержит 20 адресов одного публичного API; можно указать адреса разных сервисов. Ключи API не нужны.

## Параметры пула

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `--core` | 4 | Основное число потоков |
| `--max` | 8 | Верхняя граница числа потоков |
| `--queue` | 8 | Ёмкость `ArrayBlockingQueue` |
| `--keep-alive` | 30 | Время простоя дополнительных потоков, секунды |
| `--timeout` | 10 | Таймаут подключения и запроса, секунды |
| `--urls` | urls.txt | Файл со списком URL |
| `--output` | results.csv | CSV с результатами |

После создания основных потоков executor заполняет очередь, а при её заполнении добавляет потоки до `max`. `AbortPolicy` сигнализирует о переполнении; приложение собирает очередной завершённый результат и повторяет отправку. Поэтому задачи не теряются, очередь ограничена, а HTTP не выполняется в основном потоке.

## Результаты и мониторинг

Раз в секунду выводятся размер пула, активные потоки, очередь и число завершённых задач. В итоговой таблице: номер, URL, статус, миллисекунды, имя рабочего потока и ошибка. CSV имеет столбцы `index,url,status,time_ms,worker,error`.

Успех — HTTP 2xx. Остальные HTTP-статусы и ошибки сети учитываются отдельно. Время измеряется через `System.nanoTime()` внутри задачи: ожидание в очереди не входит в длительность запроса. Это длительность HTTP-вызова до завершения обработки тела, а не серверное время или только время первого байта. Тело ответа отбрасывается. Общая длительность пакета включает отправку задач, ожидание и закрытие ресурсов. Среднее время включает все попытки, в том числе ошибки. Запросы выполняются один раз без повторов; при перенаправлении показывается итоговый статус.

Пул закрывается через `shutdown` и `awaitTermination`, при необходимости — `shutdownNow`. Сводка показывает максимальный достигнутый размер, число завершённых задач и признак завершения пула. Недоступный API не прерывает остальные запросы.
