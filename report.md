# Отчёт по домашнему заданию № 8

**Дисциплина:** Теория и практика многопоточности  
**Тема:** Пул потоков (Thread Pool)

## 1. Подготовка проекта и входных данных

Создан Java-проект `thread-pool-homework` для JDK 21+. Внешние библиотеки не используются. В `urls.txt` записаны 20 публичных адресов JSONPlaceholder: ресурсы posts, users и todos. Программа принимает другой файл через `--urls`; адреса проверяются до запуска задач. Для IntelliJ IDEA / Giga IDE подготовлен `pom.xml`, для запуска без Maven — `run.cmd` и `test.cmd`.

## 2. Настройка собственного ThreadPoolExecutor

Пул создаётся явно конструктором `ThreadPoolExecutor`, без фабрик `Executors` в основном приложении. Настройки по умолчанию: `corePoolSize = 4`, `maximumPoolSize = 8`, `keepAliveTime = 30 секунд`, очередь `ArrayBlockingQueue` ёмкостью 8. `ThreadFactory` задаёт имена `http-worker-N`, политика отказа — `AbortPolicy`.

Когда основные потоки заняты, новые задачи попадают в очередь; после заполнения очереди пул растёт до максимума. При переполнении приложение получает завершённый результат и повторяет отправку задачи. Задачи не теряются и не переносятся для выполнения в основной поток. Все параметры доступны через аргументы командной строки.

## 3. Асинхронные HTTP-запросы

Каждый URL оформляется как `Callable<Result>` и передаётся в `ExecutorCompletionService`, использующий собственный пул. Внутри рабочего потока выполняется синхронный `HttpClient.send`; относительно вызывающего потока задачи запускаются асинхронно и выполняются параллельно. `sendAsync` не используется, чтобы прикладные HTTP-задачи выполнялись именно в настроенном executor.

Настроены таймаут подключения и таймаут запроса; по умолчанию — 10 секунд. Тело ответа отбрасывается, сохраняется итоговый статус после перенаправлений. Ошибки соединения и таймауты превращаются в результаты отдельных задач и не останавливают весь пакет.

## 4. Сбор результатов и мониторинг

Результаты собираются по мере готовности, затем сортируются по исходному порядку URL. Для каждого запроса выводятся адрес, HTTP-статус, длительность в миллисекундах, имя рабочего потока и ошибка. Время измеряется через `System.nanoTime()` внутри задачи, без ожидания в очереди; это длительность HTTP-вызова с обработкой ответа.

Раз в секунду монитор выводит текущий размер пула, число активных потоков, длину очереди и количество завершённых задач. Сводка содержит число ответов 2xx, остальных HTTP-ответов и сетевых ошибок, минимальную, среднюю и максимальную длительности, общее время пакета. Результаты сохраняются в CSV. После выполнения вызываются `shutdown()` и `awaitTermination()`, при необходимости — `shutdownNow()`.

## 6. Сопоставление типов пулов

| Тип                            | Особенности                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| FixedThreadPool                | Постоянное число потоков; стандартная фабрика использует неограниченную очередь                               |
| CachedThreadPool               | Переиспользует простаивающие потоки и создаёт новые по необходимости; число потоков потенциально очень велико |
| SingleThreadExecutor           | Один рабочий поток, последовательное выполнение задач                                                         |
| Собственный ThreadPoolExecutor | Явные границы числа потоков и очереди, собственная фабрика и политика отказа                                  |

Для данного приложения выбран собственный executor: сетевые запросы удобно выполнять параллельно, ограничивая нагрузку. Остальные типы приведены для сопоставления; основное требование задания реализовано вручную настроенным `ThreadPoolExecutor`.
